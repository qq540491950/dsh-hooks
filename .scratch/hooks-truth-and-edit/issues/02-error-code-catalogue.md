# 02: 错误码目录与用户文案表合一

**What to build:** 使用者遇到的每一种失败，都能读到一句针对那一种情形的话，而不是一个内部码。宿主能返回的错误码收成唯一一份目录，客户端的"一句话文案表"按它逐项对齐，补齐目前漏掉的几种（拿不到文件版本而拒写、写入基础设施失败、目标路径解析失败、插件内部错误、越界）；并加一条表驱动断言：目录里的每个码都必须有非默认文案，缺一项即红。这样以后新增错误码不会静默漏文案。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 宿主侧存在唯一一份"可返回错误码"目录，客户端文案表按它逐项对齐（两处不各写一套）
- [ ] 目前会露出的内部码（拿不到版本、写入失败、解析失败、内部错误、越界）都有各自的一句话
- [ ] 新增表驱动断言：目录内每个错误码都命中专属文案，未命中即失败；并做过反向验证
- [ ] 兜底的"未知码"分支仍然保留，但目录内的码不会命中它
- [ ] 文案里不出现 markdown 记号、内部字段名、盘符路径，也不出现问句式的"失败（xxx）"
