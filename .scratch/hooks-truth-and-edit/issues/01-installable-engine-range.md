# 01: 包能在当前 DSH 上安装

**What to build:** 使用者能在当前版本的 DSH 上安装并激活这个插件，插件卡片上的描述只讲它做什么。当前阻碍是：包清单把 DSH 版本钉在一个 prerelease 精确版本上，而运行时已经走到另一个 rc——按 npm 的 semver 规则，任何带 prerelease 元组的范围都不匹配"另一个元组"的 rc，于是安装/激活被引擎检查挡下来。本票把"对 DSH 的版本要求"从"钉死某个 rc"改成"不含 prerelease 元组的声明"，并把"最低支持版本"降级为文档声明 + 断言；同时清掉描述里的内部座位号。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 包清单里的 DSH 引擎要求不含任何 prerelease 版本元组（或整体缺省），并有产物级断言守住这个形状
- [ ] 插件描述只描述功能，不出现座位顺序号等内部标识，并有断言
- [ ] 在 0.2.1-rc.3 运行时上用 bundle 路线安装并激活成功，设置导航出现 Hooks 一格（安装动作需用户执行，本会话审批关闭）
- [ ] 安装后座位台账里出现 hooks 占位，且排在 mcp/900 与 skills/910 之后
- [ ] 规则文档与 README 里"本机已装 / 已生效 / 引擎已落地"这类状态记载与机器现状一致
- [ ] 上述两条元数据断言做过反向验证（注入违规 → 精确报错 → 还原）
