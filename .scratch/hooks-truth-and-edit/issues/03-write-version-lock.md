# 03: 写前版本锁（改不到别的 hook 上）

**What to build:** 页面上的每次保存都基于"我正在看的那个版本"。写请求携带使用者当时看到的那份文件版本，宿主优先用它做乐观锁，而不是自己重新读一份再锁——于是"页面渲染 → 我点按钮"这段窗口也被纳入保护。别人刚改过文件时，我会收到"文件被别处改过了，刷新后再改"，而不是让停用/改命令/删除静默落到错位的文件下标上（那会作用到另一条 hook 上，且删除不可撤销）。

三种取值语义必须逐条一致：给字符串 = 按该版本替换式写入；给 `null` = 目标必须不存在（新建）；缺省 = 旧客户端，回退到现状行为。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 页面发出的每个写请求都带"我看到的那份版本"，取值来自快照；当时文件不存在则显式表示"应为新建"
- [ ] 宿主按请求里的版本锁定写入，与实际不符返回版本冲突错误码，页面给出"文件被别处改过了，请刷新后再改"这一类文案
- [ ] 页面加载后目标文件被删除时，带版本写入返回冲突，页面不会静默新建出文件
- [ ] 不传该字段的旧客户端行为与改动前逐字一致（向后兼容路径有断言）
- [ ] 断言（数据面路由层，真 handler + 假文件系统）：注入"版本不符"，确认拒写且文件字节未变；做过反向验证
- [ ] 断言：两个并发写后到的那个拿到版本冲突，先到的那个生效
