# 06: 文件里有、但我跑不了的那些必须有归属

**What to build:** 页面不再把"有内容但我跑不了"说成"没有内容"。目前三类东西会被解析器静默丢掉：非 command 的 handler、没有 command 的条目、以及 matcher 非法而被跳过的一整组。结果是我在页面上什么都看不到，点试运行还被告知"这一条已经不在了"——它明明就在文件里。

本票在**同一次解析**里把这些"被跳过的东西"结构化记录下来（执行语义一字不改：可运行的集合与改动前逐项相同，禁止把它们混进可运行集合），让快照带上"跑不了的组"与"跑不了的条数"，页面据此：为被拒的组渲染灰化的「不会运行」行（带原因，不提供试运行）；把空状态从两种情形扩到四种；把"文件里总条数"与"能跑的条数"分开说；把试运行的"这条被拒"与"这条不在了"分成两个错误码。

**Blocked by:** 02

**Status:** ready-for-agent

- [ ] 解析结果同时给出可运行的组、被跳过的 handler（带文件下标）、被拒的组（带原因与条数），执行语义不变
- [ ] 主列表为被拒的组渲染灰化行：带「不会运行」标签、原因说明，以及「⋯」（其中不提供试运行）
- [ ] 空状态区分四情形（不存在 / 存在但 0 条 / 存在但全部跑不了 / 读不出来），"全部跑不了"给出条数与原因，绝不显示"还没有任何 hook"
- [ ] 文件总条数与可运行条数分开呈现（例如"4 条 · 其中 3 条跑不了"）
- [ ] 试运行对"组存在但被拒"与"目标不在了"返回不同错误码，页面文案不同
- [ ] 断言走真解析器 → 真快照 → 真渲染（禁止手工构造解析结果），并修复现有那条"用不可能发生的输入换来的绿"断言
