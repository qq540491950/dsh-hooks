# 17: 可达性（焦点、播报、可访问名）

**What to build:** 键盘与读屏用户能完整走一遍"看 → 改 → 知道失败原因"。现在的缺口：在底部「更多」里点 `＋` 打开的新建表单出现在页面顶部，屏幕还停在底部，看起来像"点了没反应"；保存失败、试运行结果、读取失败都没有播报；一排开关的可访问名都是"启用/停用"，无法分辨属于哪条 hook；作用域下拉承诺了高亮项语义却没真正设 `aria-activedescendant`，键盘移动时读屏不知道高亮在哪。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 打开新建表单或进入编辑态时，焦点落到第一个可编辑字段，并被滚动到可见区域
- [ ] 保存失败、试运行结果、读取失败通过 aria-live 播报（各自不重复播报）
- [ ] 开关的可访问名包含事件名与命令摘要，不再是一排同名"启用/停用"
- [ ] 作用域下拉设置 aria-activedescendant，键盘上下移动时高亮项可被读屏识别
- [ ] 断言（渲染层）：检查上述属性值、焦点转移与播报容器的存在与更新
