# 05: 删组不留空壳 + 畸形事件键拒写

**What to build:** 两件"工具别把我的文件越改越乱"的事。第一，删掉某组里最后一条 hook 时，那一组也一起从文件里消失，而不是留下 `{"matcher":"…","hooks":[]}` 这种解析器会丢弃、页面看不见、又永远删不掉的空壳。第二，当某个事件的值存在但不是数组（我手写坏了）时，新增类操作必须拒写并说明，而不是把那段结构整段覆盖掉——因为保留性证明只保护"我声明的改动之外"的字段，对"我改的就是整个键"这种操作它是失效的。

**Blocked by:** 02

**Status:** ready-for-agent

- [ ] 删除组内最后一条 hook 后，文件中该组整体消失（不残留空 hooks 数组）
- [ ] 该操作仍然通过保留性证明（声明两处下标删除，分属不同数组），未知键（如 `_comment`）原样保留
- [ ] 事件键存在但不是数组时，新增类操作拒写并返回独立的、有专属文案的错误码，文件字节不变
- [ ] 两条路径都有断言（真文件系统写入后比对字节），并做过反向验证
- [ ] 页面在拒写时给出与该错误码对应的一句话，不把内部原文当主文案
